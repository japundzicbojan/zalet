# Deploy Zalet (Render + Convex)

Partner API keys are already in local `.env.local`. What’s left for the jury is a **public URL**, plus optional Convex durability.

## 1. Render (do this for the live link)

1. Put this repo on GitHub/GitLab (or connect the current remote in Render).
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**.
3. Pick the repo. Render reads `render.yaml` (disk + health check included).
4. Fill secrets (same values as `.env.local`):

| Key | Notes |
| --- | --- |
| `FIRECRAWL_API_KEY` | live scrape |
| `EXA_API_KEY` | trends |
| `XAI_API_KEY` | Grok plan/scripts |
| `FAL_KEY` | UGC stills |
| `DAYTONA_API_KEY` | pack sandbox |
| `ZALET_RUN_SECRET` | auto-generated by Blueprint, or paste your own |
| `NEXT_PUBLIC_CONVEX_URL` | only after Convex step |

`ZALET_DATA_DIR=/var/data` is already set via the Blueprint disk.

5. Deploy → copy `https://….onrender.com`. That is the demo URL.

Post-deploy smoke:

```bash
curl -s https://YOUR-SERVICE.onrender.com/api/health
BASE_URL=https://YOUR-SERVICE.onrender.com pnpm demo:smoke
```

## 2. Convex (optional, recommended)

Survives Render restarts / multiple instances.

```bash
pnpm convex:dev
# creates a project and prints NEXT_PUBLIC_CONVEX_URL

# later / CI:
CONVEX_DEPLOY_KEY=... pnpm convex:deploy
```

Add `NEXT_PUBLIC_CONVEX_URL` on Render and redeploy.

File store stays primary; `src/lib/convex-sync.ts` dual-writes when the URL is set.

## 3. Local production check

```bash
pnpm build
pnpm start -- -p 43123
pnpm demo:smoke
```

## Notes

- No disk and no Convex ⇒ runs vanish after Render restart.
- Never commit `.env.local`.
- Rotate partner keys after the hackathon if they were pasted in chat.
